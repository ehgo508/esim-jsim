# Feature Specification: 국가별 요금제 조회

**Feature Branch**: `002-plan-catalog`

**Created**: 2026-11-20

**Status**: Draft

**Input**: User description: "여행 갈 나라를 고르면 그 나라에서 쓸 수 있는 eSIM 요금제(데이터 용량, 기간, 가격)를 보여준다."

## Scope

**이 기능이 다루는 것**
- 판매 중인 국가 목록 조회
- 국가별 요금제 목록 조회 (데이터 용량, 사용 기간, 가격, 통화·문자 포함 여부)
- 요금제 하나의 상세 조회
- 개발용 초기 데이터(국가와 요금제) 넣기

**이 기능이 다루지 않는 것 (MVP 이후)**
- 공급사 API에서 요금제를 자동으로 가져오는 동기화
- 관리자 화면에서 요금제 등록·수정
- 여러 나라를 묶은 지역 요금제(유럽 30개국 등), 할인, 쿠폰
- 내 폰이 eSIM을 지원하는지 확인 (005 설치 안내에서 간단히 다룸)

## Policy Summary

| 항목 | 정책 |
|------|------|
| 조회 권한 | 로그인 없이 누구나 조회 가능 |
| 국가 식별 | ISO 3166-1 alpha-2 코드 (JP, US, TH ...) |
| 노출 대상 | `status = ON_SALE`인 요금제만 |
| 가격 | 원(KRW) 단위 정수, 부가세 포함 가격 |
| 데이터 용량 | MB 단위 정수로 저장, 화면은 GB로 표시 (1GB = 1024MB). 무제한은 `unlimited = true` |
| 사용 기간 | 일(day) 단위. 기간은 현지에서 처음 네트워크에 붙은 때부터 시작 (공급사 정책을 따름) |
| 통화·문자 | 포함된 요금제만 `voiceMinutes`, `smsCount` 값이 있음. 없으면 `null` |
| 정렬 | 가격 낮은 순 기본 |
| 공급사 상품 연결 | 요금제마다 공급사 상품 코드(`providerPackageCode`)를 가짐. 004 발급에서 사용 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 국가 목록 보기 (Priority: P1)

여행자가 판매 중인 나라 목록을 보고 갈 나라를 고른다.

**Why this priority**: 요금제 선택의 시작점이다.

**Independent Test**: 초기 데이터를 넣고 국가 목록 API가 판매 중인 나라만 돌려주는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 일본, 미국에 판매 중 요금제가 있고 프랑스는 없음, **When** 국가 목록을 조회하면, **Then** 일본과 미국만 나온다.

---

### User Story 2 - 국가별 요금제 보기 (Priority: P1)

여행자가 일본을 고르고, 일본 요금제를 가격, 용량, 기간과 함께 본다.

**Why this priority**: 결제할 상품을 고르는 화면이다.

**Independent Test**: `JP` 요금제 목록을 조회해 판매 중인 것만 가격 순으로 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 일본 요금제 3개 중 1개가 판매 중지, **When** `JP` 목록을 조회하면, **Then** 판매 중인 2개만 가격 낮은 순으로 나온다.
2. **Given** 없는 국가 코드 `XX`, **When** 조회하면, **Then** `PLAN-2001` 에러가 난다.

---

### User Story 3 - 요금제 상세 보기 (Priority: P2)

여행자가 요금제 하나를 눌러 상세 정보(통화·문자 포함 여부, 주의사항)를 본다.

**Why this priority**: 결제 전 마지막 확인 화면이다. 목록만으로도 주문은 가능해서 P2.

**Independent Test**: 요금제 ID로 상세를 조회한다.

**Acceptance Scenarios**:

1. **Given** 판매 중인 요금제, **When** 상세를 조회하면, **Then** 모든 정보가 나온다.
2. **Given** 판매 중지된 요금제, **When** 상세를 조회하면, **Then** `PLAN-2002` 에러가 난다.

### Edge Cases

- 국가 코드는 소문자 `jp`로 와도 `JP`로 처리한다.
- 공급사 상품 코드는 내부 정보라 응답에 넣지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 판매 중인 요금제가 1개 이상 있는 국가 목록을 보여줘야 한다.
- **FR-002**: 시스템은 국가별 판매 중 요금제를 가격 낮은 순으로 보여줘야 한다.
- **FR-003**: 시스템은 요금제마다 데이터 용량, 기간, 가격, 통화·문자 포함 여부를 보여줘야 한다.
- **FR-004**: 시스템은 판매 중지된 요금제를 목록과 상세에서 숨겨야 한다.
- **FR-005**: 시스템은 개발 환경에서 초기 데이터를 자동으로 넣을 수 있어야 한다.

### Key Entities

- **Country**: 판매 국가. 국가 코드, 한국어 이름, 국기 이모지.
- **Plan**: 판매 상품. 국가, 이름, 데이터 용량, 기간, 가격, 통화·문자, 판매 상태, 공급사 상품 코드.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 3번 이하의 클릭으로 원하는 나라의 요금제 목록에 도달한다.
- **SC-002**: 판매 중지 요금제가 어떤 API에서도 노출되지 않는다.

## Assumptions

- MVP는 단일 국가 요금제만 판매하고, 초기 데이터는 일본, 미국, 태국, 베트남 4개국 정도로 시작한다.
- 가격은 공급사 원가에 마진을 붙여 직접 정한다 (학습용이라 임의 값).
